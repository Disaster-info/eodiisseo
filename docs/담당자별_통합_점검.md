# 담당자별 통합 점검 및 수정 요청

2026-10-30, `integration/backend-develop`의 `4109dea`와 이번 로컬 수정 기준이다. 실제 코드에서 확인한 연결 누락과 수정 요청을 기능 담당별로 정리했다. 다른 담당 기능과 모바일 코드는 수정하지 않았다. 이 문서는 변경 이력이 아니라 담당자에게 전달할 작업 목록이다.

우선순위는 P0=통합 실행·실서비스 연결을 막는 작업, P1=실제 앱 검증 전 완료할 작업, P2=운영·품질 보완이다. 빌드 통과와 실제 앱 연동 완료를 구분한다.

## 5. 공통 설정·CI 담당에게 전달

- 현재 backend CI는 develop/main만 대상으로 한다. 통합 브랜치 검증을 CI에서도 수행할지 팀 규칙을 정한다.
- `SPRING_PROFILES_ACTIVE=test`는 담당 운영 Bean 상당수를 제외한다. 기본 컨텍스트 테스트 성공만으로 실제 인증·Flyway·JPA·HTTP 기동을 보장하지 않는다.
- 새 DB 전체 migration과 레거시 assigned migration을 중복 실행하지 않는다. 이번 로컬 수정의 기본 경로는 `classpath:db/migration` 하나다. assigned 이력이 있는 기존 DB는 현황 확인 후 별도 전환 계획이 필요하다. baseline/repair/clean으로 이력 불일치를 숨기지 않는다.
- 로컬 DB 테스트는 별도 loopback audit 클러스터를 사용하는 구조다. CI 서비스 DB에서도 같은 검증을 실행하려면 테스트 접속·격리 계약을 합의해 CI job을 구성한다. 테스트 guard를 임의로 삭제하지 않는다.
- `.env.example`에는 발급값이 아닌 항목과 기본값만 둔다. 실제 키와 DB 비밀번호를 공유할 때 Git에 넣지 않는다. API 키 재발급이 기본 할 일이 아니라 기존 발급키의 서비스별 연결 확인이 필요하다.
- 배포 전에는 실제 origin만 CORS에 허용하고 mock flag를 끈다. 외부 API 실호출·실기기 로그인·Push·행정경계 적재를 단위 테스트와 구분해 검증한다.
