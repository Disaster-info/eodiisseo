# 백엔드 담당 기능 개발 가이드

회원·그룹·날씨·체크리스트·관리자·DB에 위치·관심지역·재난·수집을 연결한 현재 로컬 코드 기준이다. 프런트·AI·대피소·경로 담당의 코드는 변경하지 않는다. 실제 사용자 인증은 Google ID 토큰 또는 Kakao 액세스 토큰이 있어야 검증할 수 있다.

## 실행

아래 명령은 저장소 루트 PowerShell에서 실행한다. `.env`의 DB 비밀번호는 실제 로컬 DB와 일치해야 한다. `.env.example`로 기존 `.env`를 덮어쓰지 않는다.

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\backend\scripts\database\Start-LocalDatabase.ps1
.\backend\scripts\database\Start-LocalDatabase.ps1 -Audit
$build = Join-Path $env:TEMP 'eodiisseo-domain-build'
.\backend\scripts\database\Test-LocalDatabase.ps1 -BuildOutputDir $build
.\backend\scripts\database\Run-LocalBackend.ps1 -SkipBuild -BuildOutputDir $build
```

Flyway는 기존 세 migration을 수정하지 않고 `V2026110201`을 추가 적용한다. 원문 현재값과 수정 이력을 별도 테이블에 저장한다. 기존 assigned migration DB에 강제로 baseline/repair를 적용하지 않는다.

## 회원 위치와 관심지역

모든 요청에 로그인 후 발급받은 서비스 Bearer 토큰이 필요하다. 다른 회원 ID는 입력받지 않는다.

| API | 입력 | 결과 |
|---|---|---|
| `PATCH /api/v1/members/me/location-consent` | `{"consented":true}` | 서비스 내부 위치 이용 동의 |
| `PUT /api/v1/members/me/location` | `{"latitude":37.5665,"longitude":126.978}` | GPS 최신 한 건과 서버 갱신시각 |
| `POST /api/v1/interest-areas` | `{"regionCode":"등록된 SIGUNGU 코드","displayName":"우리집"}` | 등록 201 |
| `GET /api/v1/interest-areas` | 없음 | 본인 관심지역 목록 |
| `PATCH /api/v1/interest-areas/{id}` | `regionCode` 또는 `displayName` | 본인 지역 수정 |
| `DELETE /api/v1/interest-areas/{id}` | 없음 | 삭제 204 |

동의 철회는 회원 잠금 아래 GPS 삭제·모든 그룹 공유 OFF를 같은 트랜잭션에서 처리한다. 재동의해도 공유를 자동 복원하지 않는다. 위치는 DB에서 직접 읽으므로 별도 위치 캐시에 철회 전 값이 남지 않는다. 수동 조회 좌표는 저장하지 않는다. 위치 쓰기 제한의 초기 운영값은 분당 60회이며 `LOCATION_WRITE_REQUESTS_PER_MINUTE`로 변경한다. 앱의 60초 갱신 목표와 다른 설정이다.

관심지역은 실제 등록된 활성 SIGUNGU만 허용하며 중복·5개 제한·수정·삭제 소유권을 검증한다. 등록/수정과 알림 지역 선택은 같은 회원 행을 잠가 동시 요청을 직렬화한다.

## 행정구역 자료 적재

`POST /api/v1/ops/admin-areas/import`는 OPS 전용이며 `{"areas":[...]}`를 받는다. 이 API는 외부 자료를 자동 다운로드하거나 진위를 인증하지 않는다. 운영자가 출처와 이용조건을 확인한 공식 자료를 전달한다.

[행정안전부 공식 시군구법정경계](https://www.safetydata.go.kr/disaster-data/view?dataSn=900)의 공개 SHP·SHX·DBF 원본을 `backend/build/reference/admin-areas`에 확보했다. 같은 폴더의 `provenance.json`에 출처·다운로드 주소·SHA-256을 기록했다. 이 폴더는 Git 제외 대상이다. 포털 파일 날짜는 2026-10-06이지만 경계 기준년도와 동일하다고 확정하지 않았다. PRJ가 제공 목록에 없어 원본 좌표계 확인 전에는 변환·운영 DB 적재를 하지 않았다. 다운로드가 됐다는 사실만으로 위치 판정 준비 완료로 취급하지 않는다.

각 항목은 다음 필드를 사용한다.

| 필드 | 입력 |
|---|---|
| `regionCode`, `name`, `level` | 공식 코드·명칭, `SIDO`/`SIGUNGU`/`EUPMYEONDONG` |
| `parentRegionCode`, `active` | 상위 코드 또는 null, 활성 여부 |
| `sourceUrl`, `sourceProvider`, `sourceAreaCode` | 인증정보 없는 출처 URL, 제공처, 원본 코드 |
| `baseYear`, `sourceUpdatedAt` | 실제 기준년도, ISO-8601 자료 갱신시각 |
| `latitude`, `longitude` | 확인된 중심 좌표 쌍 또는 둘 다 null |
| `boundary` | WGS84 GeoJSON Polygon/MultiPolygon 또는 null |

한 요청은 1~1000개이며 전부 성공하거나 전부 롤백한다. 위·경도, 유효 폴리곤, 출처, 구버전 덮어쓰기를 검사한다. 좌표계를 변환하지 않으므로 제공 전에 EPSG:4326으로 변환해야 한다. 경계를 만들거나 중심점을 임의 추정하지 않는다. 경계가 없으면 그룹 영향은 UNKNOWN, 대시보드 좌표 지역 확인은 의존성 오류로 유지한다.

## 외부 자료 수집

현재 연결된 제공처는 네 개다. 나머지 API는 환경변수가 있어도 수집 구현 완료 상태가 아니다.

| source | 저장·해석 |
|---|---|
| `KMA_EARTHQUAKE` | 원문·수정 이력. 실제 발생시각과 유효 진앙 좌표가 있는 발표만 재난으로 투영 |
| `KMA_WARNING` | 특보 발표 원문. 상세 구역·발효/해제 코드 계약 확인 전 영향/재난 상태 추정 금지 |
| `SAFETYDATA_DISASTER_MESSAGE` | 재난문자 원문. 생성시각은 발생시각이 아니고 수신지역은 피해범위가 아님 |
| `SAFETYDATA_EARTHQUAKE_SHELTER` | 원문과 canonical shelter 테이블 저장. 수용정원은 현재 빈자리 수가 아님 |

worker는 초기에는 꺼져 있다. 기존 `.env`에 다음 값을 설정하고 백엔드를 재시작하면 주기 수집과 접수가 동작한다. 실행 중인 수집을 의도치 않게 켜지 않도록 자동으로 `.env`를 바꾸지 않는다.

```dotenv
COLLECTION_WORKER_ENABLED=true
COLLECTION_POLL_INTERVAL_MS=1000
COLLECTION_SCHEDULE_INTERVAL_MS=60000
```

첫 주기 검사 이후 제공처별 간격으로 작업을 등록한다. API 키가 없는 제공처는 자동 등록하지 않는다. 접수/실패/성공은 `collection_run`, 전체 갱신은 `collection_batch`, 임대는 `collection_job_lock`에 저장된다. HTTP 조회는 DB 트랜잭션 밖에서 수행한다. 페이지마다 임대를 갱신하며 중복 요청은 409, 중단된 임대는 FAILED로 종료한다. 실패·부분 페이지·빈 결과를 이유로 기존 대피소를 삭제하지 않는다. MOCK 수집은 지원하지 않는다.

OPS 토큰을 사용한 수동 호출:

```powershell
$headers = @{Authorization="Bearer $accessToken"}
Invoke-RestMethod 'http://127.0.0.1:8080/api/v1/ops/collections/sources' -Headers $headers
Invoke-RestMethod 'http://127.0.0.1:8080/api/v1/ops/collections' `
    -Method Post -Headers $headers -ContentType 'application/json' `
    -Body '{"source":"KMA_EARTHQUAKE"}'
Invoke-RestMethod 'http://127.0.0.1:8080/api/v1/ops/status' -Headers $headers
```

대피소 갱신은 기존 `POST /api/v1/ops/shelters/refresh`를 사용한다. 제공처와 실행 구현을 확인하고 DB에 작업이 등록된 뒤에만 202를 반환한다. 다른 담당의 대피소 조회는 아직 메모리 저장소를 사용하므로 canonical shelter DB 조회 전환은 대피소 담당에게 연결을 요청한다.

원문 식별은 제공처별로 분리한다. 기상청 발표는 연월·관서·일련번호를 함께 사용하고 지진 발표 유형도 구분한다. 정정/후속 발표를 같은 지진 사건으로 통합하는 공식 연결 규칙은 추가 확인이 필요하다. 서로 다른 발표를 임의로 하나의 사건으로 합치지 않는다. 규모→심각도, 진앙→영향지역, 발표→해제 같은 변환은 하지 않는다.

대시보드 주요 재난, 알림 관심지역·재난·심각도 Port에 읽기 어댑터를 제공한다. 재난 목록/상세의 기본 정렬·보관·대표 원문·freshness 정책은 AI 담당과 확정해야 하며 해당 HTTP Controller는 다른 담당 범위다. 알림 인증은 `eodiisseo.notification.auth.enabled=true`일 때 새 Repository 어댑터가 적용되고 기존 인증 Bean은 중복 생성되지 않는다.

## 검증과 남은 작업

실제 PostgreSQL에서 동의 철회/GPS 경합, 관심지역 동시성·소유권·5개 제한, 출처·경계 적재, 원문 이력·중복, 실제 발생시각 투영, 영향지역 우선순위, 수집 중복/실패/임대 만료와 전체 회귀를 검증한다. 외부 API 실호출과 사용자 로그인 성공은 별도로 구분한다.

현재 전체 검증은 805개 중 794개 통과·11개 조건부 건너뜀·실패 0개다. 별도의 실제 날씨 조회 테스트 1개도 통과했다. 지진·특보·재난문자·지진대피소 외부 API는 각 한 페이지의 정상 응답과 필드명을 확인했다. 수집 worker의 전체 실데이터 적재는 이 확인과 구분한다. 개발 DB의 추가 migration 적용 및 새 API의 미인증 401, 웹 HTTP 200과 백엔드 재기동도 확인했다.

남은 작업은 공식 행정경계 실자료 적재·영향지역 코드 계약 연결, 나머지 외부 API 수집기, 지진 후속 발표의 사건 통합 규칙, 실기기 소셜 로그인, 프런트 API 연동, AI 담당 HTTP API 및 대피소 담당 DB 조회 연결이다. 키 입력만으로 이 작업들이 완료되지는 않는다.

```powershell
.\backend\scripts\database\Stop-LocalBackend.ps1
```
